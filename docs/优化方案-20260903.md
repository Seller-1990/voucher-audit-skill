## 二、优化项清单

### P0 正确性/可读性缺陷（建议本迭代修）

**P0-1 客户归属一致性：命中原因不指明不一致字段**
- 现象：报告首行命中原因为"实际客户与映射表不一致"，但回源验证发现：`客户调整校验` 08 月映射（账载=某装备制造客户A → 实际=某车辆制造客户B）与源行的实际客户其实一致，真正不一致的是**部门键**（源行部门名 vs 映射表部门名）。
- 影响：审核人员按"实际客户"排查会扑空；命中原因误导排查方向。
- 建议：`checks_customer.py` 生成原因时，逐字段比对 (账载客户,部门,项目)→实际客户 映射键，输出形如："映射键不一致：部门='…某项目' 未在映射表（账载客户+部门粒度）中命中；同键最近映射（07月）实际客户=…"。
- 预计涉及：`checks_customer.py`、`report_customer_consistency.py`。

**P0-2 报告数值精度失控**
- 现象：同比波动 sheet 指标值出现 `15859.53571428571`、`5525.059999999999` 等原始浮点。
- 建议：写入报告时对金额 round 到 2 位、比率 round 到 4 位；或设置单元格 number_format。保留全精度到隐藏列或元数据。
- 预计涉及：`report.py`（统一写出出口）、`report_pp_change.py`。

### P1 报告可用性（下迭代）

**P1-1 增加"审核汇总"sheet**
- 现象：报告无总览页，需逐 sheet 数行数才能掌握规模；`规则与内容` 只列规则定义不含命中统计。
- 建议：新增首个 sheet：目标月、数据来源文件+修改时间、每规则 问题/需确认/参考 计数、Top3 命中原因。
- 预计涉及：`report.py`。

**P1-2 run 结束输出命中统计**
- 现象：`run` 完成仅打印"完成：审核完成。"，命中规模要开文件才知道。
- 建议：完成行后追加每规则问题计数一行式汇总（与 P1-1 同源数据）。

**P1-3 问题行增加"源行号"定位列**
- 建议：income_cost 类规则输出附带源 `考核表输出.xlsx/收入成本表` 的行号（inspect 已加载 workbook，成本低），审核人员可直接跳源表。

**P1-4 同比波动"参考"行降噪**
- 现象：459 行中 367 行为"参考：最近月份/历史月均/历史累计"，问题行被淹没。
- 建议：问题行置顶排序；或将参考行拆到 `同比波动_参考` sheet；sheet 加 autofilter。

### P2 预检与工作流体验

**P2-1 inspect/preview 增加数据画像**
- 现象：inspect 只列 sheet 名与列名，不给行数与`月`值分布；12.5MB 输入在 run 前无法预估时长与覆盖月份。
- 建议：inspect 输出每个匹配 sheet 的行数、`月`去重值、目标月推断结果（"目标月=202608，依据=数据最大月"）。
- 预计涉及：`preview.py`、`file_context.py`。

**P2-2 run 重复打印规则表**
- 现象：preview 已展示过 6 条规则表，`run` 再打印一遍（约 12 行 × 宽表），agent/终端噪音。
- 建议：run 加 `--quiet`；或检测本次会话已 preview 时只打印一行"规则数：6（同 preview）"。

**P2-3 月值格式归一**
- 现象：报告"月"列为 `8`，源表为 `'08'` 字符串；`客户调整校验` 用 `'05'..'08'`。
- 建议：统一以两位字符串或 int 归一后写报告，避免人工比对时误判。
